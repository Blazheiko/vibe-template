# Конфігурація

Бекенд налаштовується лише через змінні оточення. Значення за замовчуванням і правила обов'язковості нижче взято з коду конфігураційних модулів, а не з `.env.example`.

## Як завантажується конфігурація

- `.env` читає [`dotenv`](https://www.npmjs.com/package/dotenv) через `import "dotenv/config"`. Цей рядок стоїть першим у точці входу [`src/index.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/index.ts), у [`src/sentry-bootstrap.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/sentry-bootstrap.ts), у скриптах [`src/db/create-database.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/db/create-database.ts), [`src/db/seed.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/db/seed.ts) та [`src/scripts/send-test-email.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/scripts/send-test-email.ts). Файл шукається в поточній робочій директорії процесу, тобто зазвичай це `packages/backend/.env`.
- Кожен файл у [`src/config/`](https://github.com/Blazheiko/vibe-template/tree/main/packages/backend/src/config) один раз читає `env` з `node:process` під час імпорту й повертає `Object.freeze(...)`. Якщо змінити змінну після старту, процес її не побачить.
- PostgreSQL-налаштування збирає одна функція `resolveDatabaseConfig()` у [`src/config/database.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/database.ts). Її використовують застосунок, `db:create` ([`create-database.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/db/create-database.ts)) і [`drizzle.config.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/drizzle.config.ts), тож defaults однакові всюди. [`drizzle.config.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/drizzle.config.ts) не імпортує `dotenv`.
- Булеві значення розбирає [`parseBoolean`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/vendor/utils/env/parse-boolean.ts): `true`, `1`, `yes`, `on` дають true, будь-що інше дає false, а якщо змінна не задана, береться default. Регістр має значення. У `auth.ts` є свій `parseBooleanFlag`, який приймає лише `1` або `true` без урахування регістру. Такий самий локальний парсер у `network.ts` додатково приймає `yes` та `on`.
- Після імпорту конфігурацій `src/index.ts` викликає [`validateRuntimeConfig()`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/app/start/validate-runtime-config.ts). Вона кидає помилку й зупиняє старт, якщо комбінація змінних неприпустима. Нижче ці перевірки позначено як «throw на старті».

### Production-like режим

`appConfig.isProductionLike` дорівнює `APP_IS_PRODUCTION`, якщо змінну задано. Інакше він дорівнює true, коли `APP_ENV` (або `NODE_ENV`, якщо `APP_ENV` відсутня) після `trim().toLowerCase()` має значення `production` або `prod`. Від цього режиму залежить таке:

- `SESSION_COOKIE_HOST_PREFIX` за замовчуванням вмикається, і cookie сесії отримує назву `__Host-uapi`. Тоді `APP_URL` має починатися з `https://`, інакше на старті буде throw.
- `AUTH_SMS_PROVIDER=fake` заборонено: на старті буде throw.

Окремо від `isProductionLike`, `APP_ENV` впливає на інші місця напряму:

- `secure` у cookie ([`cookies.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/cookies.ts), [`session.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/session.ts)) дорівнює `APP_ENV !== 'local'`.
- CSP `connect-src` у [`csp.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/csp.ts) не пропускає `ws:` та `http:`, коли `APP_ENV` дорівнює `production` або `prod`. Тут порівняння точне, без нормалізації.

## Ліміти тіла запиту

Значення задаються в байтах: лише додатне безпечне ціле число, записане цифрами (пробіли навколо допускаються). Будь-що інше — `abc`, `0`, `-1`, `1.5`, `1e6`, `0x10`, `Infinity`, число понад `Number.MAX_SAFE_INTEGER` — замінюється на default. Ліміт за типом тіла описано в [Життєвому циклі запиту](/backend/request-lifecycle#тіло-запиту-типи-і-ліміти).

| Змінна                        | Призначення                          | Default             | Обов'язковість (умова) | Читає файл                                                                                        |
| ----------------------------- | ------------------------------------ | ------------------- | ---------------------- | ------------------------------------------------------------------------------------------------- |
| `APP_MAX_BODY_SIZE`           | Загальний ліміт тіла                 | `2097152` (2 MiB)   | Ні                     | [app.ts](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/app.ts) |
| `APP_MAX_JSON_BODY_SIZE`      | Ліміт для JSON                       | `2097152` (2 MiB)   | Ні                     | [app.ts](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/app.ts) |
| `APP_MAX_MULTIPART_BODY_SIZE` | Ліміт для multipart                  | `52428800` (50 MiB) | Ні                     | [app.ts](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/app.ts) |
| `APP_MAX_OCTET_BODY_SIZE`     | Ліміт для `application/octet-stream` | `52428800` (50 MiB) | Ні                     | [app.ts](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/app.ts) |

Чому такі defaults:

- **2 MiB для JSON і решти типів.** Реальні JSON-тіла значно менші, а зниження до 1 MiB змінило б поведінку без вигоди.
- **50 MiB для multipart** — політика сумісності. Фактична потреба менша: файлові ліміти сервісів — 10 MB для аватара (`avatar-service.ts`) і 5 MB для скриншота бази знань (`knowledge-base-service.ts`), плюс невелика multipart-обгортка. Тож ліміт тіла можна знизити, не зачепивши наявні маршрути.
- **50 MiB для octet.** `octet`-маршрутів у шаблоні немає.

Під час розгортання:

- **Проксі.** Ліміт проксі перед backend (`client_max_body_size` у nginx, ліміти CDN) має бути не меншим за потрібний ліміт тіла, інакше великі запити відріже проксі зі своєю відповіддю, а не backend з 413.
- **Пам'ять.** Тіло збирається в пам'яті. Приблизна оцінка самих буферів тіла: `≈ кількість одночасних запитів × maxMultipartBodySize × 2`. Це не верхня межа пам'яті процесу: парсери ще створюють рядки, об'єкти й копії даних. Для аварійного зниження є `APP_MAX_MULTIPART_BODY_SIZE`.

## Відповідність .env.example

[`packages/backend/.env.example`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/.env.example) містить усі змінні, які читає бекенд, крім `NODE_ENV` (запасне джерело для `APP_ENV`). Змінних, яких код не читає, у файлі немає.

- `TURN_SECRET` і `TURN_HOST` читає [`config/turn.ts`](https://github.com/Blazheiko/vibe-template/blob/main/packages/backend/src/config/turn.ts), але цей модуль поки ніхто не імпортує.
- Назва `CREDENTIONALS_CORS` містить друкарську помилку, але саме так її читає код, тому змінювати її не можна.

Як запустити проєкт локально, див. на сторінці [Початок роботи](/guide/getting-started). Загальний огляд бекенда див. у розділі [Backend](/backend/).
