# Що вже реалізовано: акаунт і адмінка

Одна сторінка про те, які сценарії керування акаунтом і адмін-панель шаблон уже має, а які ще ні. Вона зведена з реєстру фіч (`feature_list.json` у `main`) і коду; кожен рядок веде на сторінку, де це описано докладно. Загальний огляд усіх можливостей шаблону — на [головній](/#що-вже-реалізовано).

Список сценаріїв походить із внутрішнього аналізу [`template-functionality-recommendations.md`](https://github.com/Blazheiko/vibe-template/blob/main/docs/plan/future/template-functionality-recommendations.md). Він містить пропозиції, а не погоджений план: те, чого тут немає, не обіцяне.

## Адмін-панель

Адмінка відкривається ролям, що мають хоча б один дозвіл (`isStaffRole`), на `/admin`. Меню показує лише сторінки, на які в ролі є дозвіл; кожен запит однаково перевіряє бекенд.

| Сторінка        | Шлях                    | Потрібний дозвіл       | Що робить                                                                                                    | Детальніше                                               |
| --------------- | ----------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| База знань      | `/admin/knowledge-base` | `kb.read`              | Статті, скриншоти, переіндексація однієї статті; запис — `kb.write`, усієї бази — `kb.manage`                | [AI](/backend/ai)                                        |
| Користувачі     | `/admin/users`          | `users.read`           | Список користувачів; картка користувача; зміна ролі — `users.roles.assign`; скидання MFA — `users.mfa.reset` | [Ролі та можливості](/reference/roles-capabilities)      |
| Хто онлайн      | `/admin/user-online`    | `users.read`           | Поточні користувачі в реальному часі через WebSocket                                                         | [WebSocket](/backend/websocket)                          |
| Історія онлайну | `/admin/history-online` | `users.sensitive.read` | Історія присутності з IP і user-agent                                                                        | [WebSocket](/backend/websocket)                          |
| Журнал дій      | `/admin/audit-log`      | `audit.read.account`   | Події журналу з фільтрами; без `audit.read` лише входи й сесії                                               | [Журнал дій](/backend/audit-log#сторінка-адміністратора) |

Без сторінки в інтерфейсі, лише через API:

- **AI-промпти** (`prompts.manage`): маршрути `api/prompts`, сторінки в адмінці немає.
- **Статистика використання AI** (`ai_usage.read`): `GET /admin/usage/text` і `/admin/usage/stats`.

### Ролі

| Роль               | Дозволи                                                                |
| ------------------ | ---------------------------------------------------------------------- |
| `user`             | немає доступу до адмінки                                               |
| `support_operator` | `users.read`, `audit.read.account`, `kb.read`                          |
| `kb_editor`        | `kb.read`, `kb.write`                                                  |
| `user_admin`       | `users.read`, `users.roles.assign`, `audit.read`, `audit.read.account` |
| `admin`            | усі                                                                    |

Матриця «роль × можливість» з перевіркою в коді — у [Ролі та можливості](/reference/roles-capabilities).

## Як підтримувати сторінку

Після зміни статусу фічі з цього списку оновіть відповідний рядок в обох локалях (`documentation/reference/implemented-features.md` і `documentation/en/reference/implemented-features.md`). Нова сторінка адмінки з'являється тут разом із записом у `ADMIN_PAGES`.
